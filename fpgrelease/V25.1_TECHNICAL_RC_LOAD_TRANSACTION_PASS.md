# FPG V25.1 — Technical RC: transactional LOAD

## Change
`GameEngine.loadWorld()` now performs a preflight restore before mutating the live career.

### Before
A malformed snapshot could:
1. restore `GameState`,
2. replace players,
3. replace clubs,
4. replace fixtures,
5. fail world-integrity validation,
6. return `false` with the running career already partially modified.

### Now
LOAD first constructs candidate `Player`, `Club` and fixture data and validates:
- unique club/player IDs,
- roster ownership consistency,
- club references,
- loan references,
- contract invariants,
- fixture club references,
- fixture dates,
- duplicate fixture keys,
- pending career-match fixture identity.

Only after this preflight succeeds does the existing restore path mutate the live engine.

## Release impact
This is a Technical RC hardening change. It does not add gameplay features and is intended to reduce save corruption risk before Open Beta.

## Verification note
Flutter/Dart SDK is not available in this environment, so `flutter analyze` and `flutter test` could not be executed here. The change was inspected against the current project structure and existing persistence/integrity APIs.
