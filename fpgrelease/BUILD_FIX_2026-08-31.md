# FPG — BUILD FIX 2026-08-31

## Root cause found in CI logs

The failed run reached `flutter pub get` successfully and then stopped at:

`Flutter failed to read file at android/app/build.gradle`

The submitted repository did not contain an `android/` directory. The failure therefore happened before the Dart analyzer, tests, or application build could run.

## Fix applied

The GitHub Actions workflow now:

1. pins Flutter to 3.47.2, matching the failing runner;
2. installs Java 17 explicitly;
3. checks for a complete Android Gradle scaffold, not merely the `android/` directory;
4. regenerates Android with `flutter create` when the scaffold is missing or partial;
5. verifies the Android manifest and Gradle build file before continuing;
6. runs dependency installation, launcher icon generation, analyzer, tests, APK build, and AAB build.

The check accepts both `build.gradle` and `build.gradle.kts`, so a future Flutter template change does not recreate the same failure.

## Static checks performed on the supplied archive

- All relative Dart imports resolve to existing files.
- `assets/fpg_logo.png` exists and matches the path declared by `pubspec.yaml`.
- Audio asset directories referenced by `pubspec.yaml` exist.
- The supplied build log contains one blocking build error; no Dart analyzer/test failure was reached in that run.

## Important limitation

The local execution environment used for this repair does not contain the Flutter/Dart SDK, so `flutter analyze`, `flutter test`, and `flutter build` were not falsely reported as locally executed. The repaired CI pipeline is the final verification step.
